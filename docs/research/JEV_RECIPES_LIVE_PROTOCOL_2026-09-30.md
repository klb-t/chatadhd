# Jev recipes: bounded first LIVE panel

Preregistered 2026-09-30, before any calls or results from this panel. This is an
execution continuation of `JEV_RECIPES_PLAN_2026-09-29.md`, not a new API budget.
The owner-authorized existing dedicated, nonresetting USD 2 key ceiling is shared
with all other jobs, as recorded in `JEV_LIVE_PROTOCOL_2026-09-28.md`. Current key
metadata, not a fresh USD 2 allowance per directory or batch, governs spending.
The adapter has no operation that creates a key or changes its cap.

## First 32 requests

Select all sixteen `relation` cases r01–r16 from the existing frozen T3 archive,
each with `object_meaningful` and `string`, in case-ID order with meaningful
first. Selection uses only public input bodies/index, never gold or results.
Each call retains the original two independent Noul questions `expressed` and
`inferred`, so the planned denominators are 32 calls and 64 binary decisions.
Each task/arm has sixteen decisions, eight PL/eight EN, eight authored
development/eight authored validation. Those splits are already-known synthetic
development material, not an independent blind holdout.

This subset was chosen for a complete paired comparison of source assertion
versus bounded inference on the existing relation cases, and one orthogonal
instruction representation contrast. The source contains paraphrases,
direction reversal, unsupported implementation/cause/identity, and proposed
structural abstractions. All source state and instruction values remain frozen;
the only API-body addition is the previously verified provider `max_price` cap.
The index and archive hashes, each original body hash and adapted body hash are
recorded. Gold, split, case-ID and arm metadata are never sent as state.

No explicit attributed-source query or controlled-counterfactual query exists
in these T3 bodies. Therefore this first panel cannot claim to measure those
queries. They are a subsequent, separately preregistered experiment: retain the
same source/candidate, vary source attribution versus analyst endorsement, and
pair one controlled source edit with its unchanged original; define expected
decision changes before calls. Similarly, neutral/nonsense instruction keys,
context and hierarchical routing remain competing unexecuted continuations.
Do not run the full 184-call Cartesian continuation automatically. Select the
next informative series after inspecting this first panel, record its selection
and new hypotheses before outcomes, and preserve the first panel unchanged.

## Spending and first-attempt contract

`typesafe/jev-1.13`, only `typesafe`, no fallbacks; catalog prompt price must be
at most USD 0.042 per million input tokens, completion and all ancillary charges
zero. Store fresh catalog snapshot and allowed dated model identity. Reserve
USD 0.001 per call: this panel reserves USD 0.032, inside the unchanged USD 0.10
batch cap. Finite batches have at most 64 distinct request IDs. Requests have
the existing 16 KiB body guard and at most 32 Noul questions; neither limit in
the original runner is relaxed. Reservation is a conservative tripwire, not a
proof of an external invoice bound.

Prepare uses one public catalog GET. Run checks catalog age (24 h maximum) and
current dedicated key metadata before sending any paid request and immediately
before each next attempt. The key must have a nonresetting cap no greater than
the existing USD 2 ceiling, sufficient remaining reservation, no management
privilege, and no historical BYOK spend. Positive BYOK response/audit flags,
unknown mandatory usage/cost, excess price/cost, wrong provider/model, malformed
answers or uncertain transport stop the series. Generation GET is optional,
once per response; unavailable generation metadata is not a paid retry.

Only `OPENROUTER_KEY_FILE` loads the private credential, from a private regular
file outside this repository. No discovery, inline key option, direct-key env,
credential logging or canonical graph mutation. The parent operator performs
real preflight and execution after providing the key. This preparation task
makes zero API calls, including catalog requests (tests use mocks).

Before POST, an exclusive immutable start receipt and durable ledger checkpoint
reserve the first attempt. First raw response and terminal receipt are exclusive
immutable files. A mutable ledger is only a checkpoint over these receipts.
Interrupted/unknown first attempts are never replayed; resume stops on unresolved
started attempts or reuses an already-written terminal receipt. Completed/stopped
resume is offline. A new output directory is not an invitation to repeat the
same paid request; root keeps one canonical run path for this experiment.
