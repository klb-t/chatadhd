Version `2026-10-05-v1` is recorded in [`followup-semantic-preregistration-v1.json`](followup-semantic-preregistration-v1.json), SHA-256 `9787f92838174075e34e1fa579153abbce6a28f02e57b3d653895d224163c9d8`. It covers all 12 Stage 3 requests and all 12 Stage 4 requests in the exact [accepted input freeze](followup-frontier-reply/final-verified-lineage/). This is criteria data for later evaluation; no semantic grader, live score or model winner is created here.

The criteria were derived from the prepared inputs, the existing authored Stage 3 references, and the pinned Stage 4 case inputs and compiler/prompt sources. No future live outputs or results/responses files were read for this registration. Earlier recovery work inspected historical authored/scripted mechanism artifacts, so these are known synthetic DEV controls. They are not independent unseen quality gold, holdout performance or evidence of world truth.

Compiler validity, semantic adequacy, source grounding and transport/billing are separate dimensions. Faithful paraphrase and a valid new claim ID may differ from the authored reference while preserving existing entity identity, meaning, qualifiers and support. Literal record/reference agreement remains a separate metric. Existing schema, topology, span, diff and text/tree-equality checks establish representation validity. A valid compilation can still give the wrong answer or misattribute a source. Where the original public content is unambiguously interpretable, semantic review can proceed independently of compiler failure; captured bytes are never repaired. Ambiguous or absent content stays unavailable.

All applicable content criteria are identical across models/providers and across the two Stage 4 representations. Optional semantic links may be empty, and a short answer may use only the root node. No confidence threshold, mandatory citation field, extra graph depth or external domain rule is introduced. If an answer makes source claims or emits links, the evaluator records their exact response span/pointer and maps them to the registered input evidence. Hypotheses, recommendations and model-proposed links cannot become user decisions or validated logical truth.

Every planned request remains in the denominator: 12 per stage, 6 per track/arm, and 2 per model plus track/arm. Missing, failed, unattempted or unreadable responses cannot count correct. Report adequacy and grounding pass counts alongside attempted, interpretable and compiled coverage. Conditional scores over available replies, if reported, accompany the full planned denominator. The Stage 3 tracks have different task targets, so their paired inputs do not justify a direct same-task winner comparison.

The JSON binds all request/input/prompt hashes, exact code versions, 12 source observation points and four host-derived Stage 4 spans within the hash-bound embedded fixture bytes. Original source locators are retained, including their null offsets; derived spans do not pretend to be offsets in an unavailable physical file. [Verification receipt](verification/followup-semantic-preregistration-v1.json) records the input, pair, source-span and code-hash checks. Unselected Stage 3 controls, other reply cases, Stage 5, holdout and private material are outside this registration.
