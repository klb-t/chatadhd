## 6. Trwałość sesji

Ta sesja to `claude remote-control` w `tmux` (sesja `rc`, założona 18:20) i przeżywa rozłączenie SSH. Uwaga: uruchomiono ją z literówką (`claude remote-control-name chatadhd-vm`), więc wystartowała jako zwykła sesja z promptem; Remote Control włączono potem poleceniem `/remote-control gcp`. W aplikacji widać ją jako **gcp**.
Po wywłaszczeniu i ponownym starcie maszyny nic tej sesji nie wznowi. Przygotowałem jednostkę `systemd --user` (linger jest już włączony), ale klasyfikator uprawnień zablokował jej instalację jako trwały mechanizm. Propozycja do jego tak/nie (wkleić na VM):

```sh
mkdir -p ~/.config/systemd/user && cat > ~/.config/systemd/user/claude-rc.service <<'EOF'
[Unit]
Description=Claude Code Remote Control in tmux session rc
After=network-online.target
[Service]
Type=oneshot
RemainAfterExit=yes
Environment=PATH=%h/.local/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=/bin/sh -c 'tmux has-session -t rc 2>/dev/null || tmux new-session -d -s rc -c %h/chatadhd "claude remote-control --name gcp"'
[Install]
WantedBy=default.target
EOF
systemctl --user daemon-reload && systemctl --user enable claude-rc.service
```

## 8. spot-guard: awans Spot→Standard na życzenie (właściciel, 2026-10-23 ≈ 19:10)

Polecenie właściciela: „Ustaw możliwość na życzenie automatycznego awansu ze spot do standard, w przypadku zadań pozostałych do wykonania podczas preemptingu. No i na logikę w miarę szybko żeby z powrotem na spot”. Kod jest w `tools/gcp/`:
- `spot_guard.yaml`: GCP Workflow uruchamiany co 2 min przez Cloud Scheduler (działa poza VM). Po wywłaszczeniu przy `work-pending=true` zmienia provisioning na Standard i startuje maszynę. Gdy maszyna jest awansowana i przez `spot-guard-return-idle-min` (preset 10) ma `work-pending=false`, zatrzymuje ją, przywraca zapisany harmonogram Spot i startuje.
- `work.sh pending|done|status|set`: flaga z VM.
- `preempt_hook.sh`: shutdown-script. Przy wywłaszczeniu sam ustawia `work-pending`, gdy działa build, testy lub bramka (regex `spot-guard-busy-procs` w metadanych).
- `install_spot_guard.sh [--uninstall]`: wdrożenie.
Wszystkie progi są presetami w metadanych instancji (opis w nagłówku `spot_guard.yaml`). `spot-guard-pending-ttl-hours` (preset 8, puste = bez limitu) chroni przed zapomnianą flagą.
Stan: API Workflows i Scheduler są włączone. Workflow nie jest wdrożony, bo klasyfikator uprawnień zablokował instalację. Nieprzetestowane na żywo. Znana luka: powrót na Spot wymaga zatrzymania (ok. 1–2 min przerwy). Po każdym restarcie sesję `claude rc` trzeba wznowić ręcznie, dopóki nie ma `claude-rc.service` (§6).
