# Self-hosting run: Loom compiles this repository

This directory is the output of the **Archive-to-Project vertical slice**
(MEGA MASTER §7 and §16) run over this repository. The inputs are the
architecture document, `CLAUDE.md`, the READMEs, the Python sources (`core/`,
`engine/`, `gui/`), the Loom sources (`loom/`, including server, web and
Android), and the git history. Everything here was generated by `loom archive
run`; only this README is hand-written.

| File | Contents |
|---|---|
| [`MASTER.md`](MASTER.md) | Themes, timeline per theme, decisions (superseded ones marked), rejected options, unresolved open questions, requirements, invariants, ideas, supersessions and contradictions, and a gap summary. Every claim links to its source as `[title › location @ date]`. |
| [`gap_report.md`](gap_report.md) | Spec ↔ repository. Named components and interfaces checked against declared symbols. Spec bullets checked against paths and symbols, least-covered sections first. Also: files referenced but absent, themes without code, TODO/FIXME. |
| [`source_map.csv`](source_map.csv) | Every cited source: reference, stable key, kind, title, location, date, file, theme, retrieval score and matched terms. |
| [`items.jsonl`](items.jsonl) | Typed items (decision, rejected_option, open_question, requirement, invariant, idea, rationale, implementation, bug) with confidence, cues, subject terms, status and relations. |
| [`timeline.json`](timeline.json) | Chronological events per theme, and forks (none here: the repo has no chat exports). |
| [`graph.json`](graph.json) | Themes, terms, retrieved documents and items, with `part_of`, `derived_from`, `supersedes`, `contradicts` and `resolves` edges. |
| [`project_manifest.json`](project_manifest.json) | Machine-readable project: vocabulary, themes, components with evidence status, requirements, invariants, decisions, open questions, missing files, sources. |
| [`task_log.jsonl`](task_log.jsonl) | One line per pipeline stage: input hash, output hash, counts. |

## Reproduce

```bash
cd loom && cmake --preset dev && cmake --build --preset dev && cd ..
loom/build/dev/cli/loom --data-dir /tmp/loom-selfhost archive run \
    --repo . --out docs/selfhost --project ChatADHD \
    --seed ChatADHD --seed Loom --seed provenance --seed graph \
    --seed importer --seed agent --seed archive
```

The run takes about 5 seconds. With the same commit checked out, the output is
byte-identical in any fresh data directory: no network, no random ids, no
clock. Code files are dated by their last commit, and uncommitted files are
"undated". Running it again on the same data directory is a cache hit for every
stage. Press Ctrl-C during a run to pause it; the same command resumes from
the checkpoint. The output directory holds a `.loom-archive` marker, so later
runs never ingest their own output.

## Run it on real chat exports

```bash
loom --data-dir ~/loom-archive archive run \
    --source ~/chatgpt-export.zip \
    --source ~/claude-export.zip \
    --repo . --out out/ \
    --seed ChatADHD --seed Loom --seed agent
```

- **ChatGPT** `conversations.json` (in the zip or on its own): the mapping tree
  is walked with timestamps. Each branch point becomes a fork, with the branch
  on the `current_node` path marked **kept** and the others **abandoned**
  (abandoned branches still count).
- **Claude** `conversations.json`, `projects.json` (description, instructions,
  project docs) and `memories.json`. Branches use `parent_message_uuid` when
  the export has it.
- Anything else the universal importer reads (HTML, MHT, JSONL, SQLite,
  Markdown or text transcripts) goes through the Importer. `--include-db` adds
  the conversations already in the data directory, including edit version
  groups as forks.
- Leave out `--seed` and the seeds come from a previous `project_manifest.json`
  (in the repo or `--out`), or from the project name and README terms.
- `--llm auto` uses the configured API key and `semantic_model` for graph
  analysis and to refine low-confidence items. It is optional, and it makes the
  output non-deterministic.
- The same run is available as `loom_archive_run` (C ABI) and as
  `POST /api/archive/run` (loom-server, SSE progress).

## What the self-hosting run found

**Retrieval.** Seven seeds hit 290 of 444 documents (code files, document
sections and commits; the counts are in `MASTER.md` §1). Expansion added `task, sqlite, android,
knowledge, project, loombridge, abi, directory`, then `system, kivy, storage,
sdk, zero knowledge, model, analyzer, android sdk`, then reached a fixpoint.
`MASTER.md` §2 gives the reason and evidence for each term.

**Themes.** Nine communities that match the real structure: the Android shell,
the graph and semantic layer, providers and models, the Python/Kivy GUI line,
the archive pipeline, provenance and artifacts, SQLite and the C ABI, the
importer, and the event bus.

**Items** (223). The pipeline recovers all twelve deliberately open decisions
of MEGA MASTER §10 as open questions: JSON vs YAML vs protobuf, SQLite vs
other backends, Compose MP vs other renderers, event sourcing, plugin ABI,
server topology, default provider, Web as a first-class client, and others.
It also recovers the "must not lose" lists of §11–§13 as requirements, and
the loom/README decision table with its invariant/policy/platform classes.
No supersessions or contradictions were detected. That is correct for a
repository without chat history; the fixture corpus in
`loom/tests/fixtures/archive` shows both.

**Gaps.** These are real findings, not planted ones:

- The storage/identity contracts of §4.12 do not exist as interfaces:
  `IDataStore`, `IEventStore`, `ISecretStore`, `IKeyProvider`,
  `ISyncTransport`, `IIdentityProvider` are missing. `IBlobStore` is partial:
  there is a concrete `BlobStore` in `loom/include/loom/provenance.h`, but no
  interface.
- The environment/deployment fabric of §4.8 is missing: `IExecutionEnvironment`,
  `EnvironmentManifest`, `ExecutionEnvironment`, `ComputeProvider`. The agent
  runtime of §4.7 has 1/9 features with evidence (no action decomposer, no
  tool adapters, no rollback/retry engine).
- UI IR and renderer: `ViewNode` (§4.11) is missing, and **Compose
  Multiplatform** has no code evidence (the Android shell is a WebView, not a
  Compose renderer).
- Object model (§3) names with no declaration: `SourceRef`, `RawArtifact`,
  `NormalizedArtifact` (§4.1), `ConfigIR` (§6), `GraphStore` (§8; the graph
  lives in `Database` instead).
- The "historical Agent" requirements of §11 (0/11) and §1.3 (0/7) have no
  code yet: central memory, experience distillation, GUI action → screenshot
  evaluation, local ↔ GCP portability.
- Files referenced but absent: `third_party/README.md` (cited in
  `loom/README.md`).

## Known limitations

- Items come from cue phrases (PL+EN), so implicit decisions ("ok, let's do
  that") need `--llm auto`.
- Gap matching is lexical: it uses paths, declared symbols, identifiers used in
  code, and a small PL→EN glossary. "Implemented" means the words are present,
  not that the behaviour is verified.
- Some capitalised phrases in the gap report are names of concepts in the
  documents ("Mega Master", "Project Compiler"), not components.
