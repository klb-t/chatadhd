## Should-fix

### 1. Every floating-window move shows the advisory „Nie wiem, co zrobić z … upuszczonym na okno …” while the desktop is visible
- `loom/web/src/shell/windows/WindowHost.tsx:196` dispatches `WINDOW_DRAGGED` on every drop of a floating window (not only on the trash icon).
- `loom/web/src/shell/windows/Desktop.tsx:188` resolves it with `hitsAt(d.x, d.y)` = `document.elementsFromPoint` from the top down, unless `cover === "full"` (cover `partial` = only floating windows → the handler runs).
- During the drag `WindowHost.tsx:175` moves the frame live (`a.onMove(w.id, rect, false)`), so at `pointerup` the dragged window's own frame (`[data-window]`) is the topmost element under the pointer. `hitsAt` therefore returns `[window(self), …, desktop]`.
- `desktop-interact.ts:66` (`matchTarget`) correctly refuses the self hit for every rule, and no rule takes a window on the desktop — so the loop falls through to `desktop-interact.ts:97-99`: `first = hits.find(h => h.kind !== "other")` is the **self window**, not the desktop, so the "quiet end of a window move" branch (`first.kind === "desktop" && source.kind === "window"`) is not taken and `{kind: "none", advisory: {code: "drop_no_rule"}}` is returned.
- `Desktop.tsx` `resolveAndRun` then calls `setArrNote(drop_no_rule …)` and the chip appears in the arrange bar (whenever the desktop has at least one icon).
- Scenario: desktop shown with pins, one floating chat window; drag the window's title bar anywhere over the empty desktop and release → chip "I do not know what to do with “chat” dropped on the window “chat” - the icon went back".
- The unit test (`tests/shell/windows-desktop-interact.test.mjs:54`, `resolveDrop(w, [desk])`) passes hits **without** the self window; the e2e D6 step 5 only tests the trash case. Fix: skip hits that are the source itself before choosing `first` (or filter them in `hitsAt`).
- Severity: should-fix (a wrong, noisy advisory on a basic gesture). Confidence: confirmed by reading the path.

### 2. `changed_lines` (archive lineage) now needs O(D²) memory instead of O(N+M)
- `loom/src/resolve/lineage.cpp:74` replaced the in-place Myers (one `V` of 2(N+M)+2 longs) with `text::myers_distance`, which calls `myers_script` (`loom/src/text/align.cpp:41-44`) and keeps the full trace: one copy of the `V` slice per step d, i.e. Σ(2d+1) ≈ D² longs, just to count non-equal ops.
- `changed_lines` (`lineage.cpp:78-90`) runs on the line ids of whole file contents in `code_lineage`. Two versions of a file that differ in D = 20 000 lines (a regenerated/renamed/generated file in an archive) → ≈ 4·10⁸ longs ≈ 3.2 GB; D = 40 000 → 12.8 GB. The old code used ~640 KB for the same input. On this machine (container restarts at ~95 % memory/disk) that is a crash of the whole archive run, not a slowdown.
- Fix: keep a distance-only Myers (no trace) for `myers_distance`, or cap D and fall back.
- Severity: should-fix (blocking for large archives). Confidence: confirmed by reading.

### 3. A guest whose bundle holds no conversation still restores + reloads on every visit (and `replace`s the working copy each time)
- `loom/web/src/components/GuestLayer.tsx:85-115`: the fix stops the infinite loop with a one-shot `sessionStorage` mark (`justRestored`), consumed on the page that follows the reload. The emptiness test is still "`/api/conversations?limit=1` is empty" (line 112), while `bundleSize` counts every table row and memory entry (`context/guest-store.ts:83-89`).
- So for a bundle of pins/layout/settings only: visit → restore (`mode=replace`, `guest-store.ts:144-148`: "exactly the bundle, also over what the page wrote") → reload → skip (mark consumed). The **next** navigation or manual reload: mark gone → restore → reload again. Every visit costs two page loads and one `replace` of the server working copy with the browser's last saved bundle; anything written to the working copy since the last debounced save (`SAVE_DEBOUNCE_MS`, or a save that failed) is overwritten. The new e2e `guest-restore-no-loop.mjs:57` asserts `n <= 2` — it codifies the extra reload rather than the absence of a restore.
- Fix: decide "working copy empty" from what the bundle holds (e.g. compare the working copy's own row count / a bundle hash kept with the working copy), not from conversations alone.
- Severity: should-fix. Confidence: confirmed by reading.

### 4. `placeIcons` in `free` mode stacks a flowing icon under a hand-placed one (P4 claim "never stacks an icon")
- `loom/web/src/shell/windows/desktop-arrange.ts:150-162`: in the `free` branch a hand-positioned icon is placed (`pinned: true`) and `continue`s **without** adding its cell to `taken`; the icons without a position then take cells from `cellsInFlow` starting at (0,0), skipping only `taken`. The grid branch does add pinned cells (line ~185).
- Scenario: `mode: "free", snap: true`; the person drags icon A to the first cell; a new pin B (first in declaration order) flows to (0,0) → B is drawn exactly under A (same x, y, same size), invisible and not clickable. With `snap: false` the same happens whenever A's snapped cell is a flow cell.
- The property test deliberately skips the "no two icons on one cell" assertion for free mode (`tests/shell/windows-desktop-arrange.test.mjs:144`), which is how it stayed green.
- Severity: should-fix (an icon disappears; the module header promises the opposite). Confidence: confirmed by reading.

### 5. Genesis materialisation is not idempotent across fragment levels: event nodes are shared by key that lacks the level
- `loom/src/text/genesis.cpp:19` `event_key(kind, from, to, a, b)` has no `level`; `materialize` reuses nodes by `(label, kind)` (`genesis.cpp:374`, `node(e.key, ev_kind, …)` → `db.find_node`). Version nodes are keyed by message id alone, and `opt.node_kind("event")` is the same for every level.
- Scenario: the same version group materialised at `level: "sentence"` and then at `level: "paragraph"` (both are open options of the call: `ops.cpp genesis_setup`, `capi_text_genesis.cpp setup`). The paragraph run finds the sentence run's event node `delete|m1|m2|3|-` (indexes coincide by chance — index 3 of a different unit), reuses it (content/metadata of the sentence event kept), and adds a second `about` link to the paragraph fragment; the version node keeps `level: "sentence"` in its metadata and the `version_chain` link metadata is overwritten with the other level. The graph now answers `origin`/`replaced` with mixed-level events. The header (`text_genesis.h:15-18`) promises "running it twice leaves the graph as after once" — true for one level only.
- Fix: put the level into the event key (and into the version node label or kind), or refuse a second level with an advisory.
- Severity: should-fix. Confidence: confirmed by reading.

## Minor

### 6. Dev server (React StrictMode) still loops on restore
`main.tsx:8` wraps the app in `StrictMode`, which runs the effect twice in development. Run 1 consumes `RESTORED_KEY` (`justRestored = true` in its own closure) and is cancelled (`live = false`); run 2 sees no key, `justRestored = false`, restores and reloads → infinite reload with `npm run dev` for a pins-only bundle. Production builds are not affected. (`GuestLayer.tsx:85-88`). Plausible, not run.

### 7. `genesis.missing` through the C ABI with only `conv_id` fails when the first group has no version group
`genesis.cpp:533`: `versions_of_group(db, chains[0].versions.front().source.group)` — for a message without `version_group_id`, `group == message id` (`SourceRef::from_message`), so `db.get_versions(id)` is empty → `NotFound "version group not found"` instead of the `first_version` answer. The action path (`ops.cpp genesis_ask`) always sets `message_id`, so only `loom_text_genesis_query` is affected. Confirmed by reading.

### 8. Receipt/undo gaps versus the P3 model
`App.tsx deskDrop`: the `close` step shows a receipt without an undo, although `applyStep` defines `reopen` as its inverse; `Desktop.tsx toTrash` returns silently (no advisory) when a non-trashable icon is dropped on the trash (`resolveAndRun` → `toTrash` → `!trashable → return`), e.g. a `window_kind:` or `layout:` icon. The set_param undo writes `before === undefined` through `coupling.write` when the parameter had no value — whether `setParam` treats `undefined` as "remove" was not verified.

### 9. `fillValue` uses `String.replace` with a string pattern
`desktop-interact.ts:109-110`: `$&`, `$'`, `` $` `` and `$$` inside an address would be interpreted as replacement patterns; a `$rest` text inside the address itself would be replaced too. Addresses today (`conv:c_…`, `party:…`) contain neither. Plausible only for addresses from data.

### 10. Grid drop row estimate uses the whole `.desktop-icons` box
`Desktop.tsx dragEnd`: `rowH = r.height / pl.rows`, where the box also contains the icon menu and the hint/advisory paragraphs (children of the grid div) — when a hint is shown, rows are over-estimated and a drop near the bottom lands one row too high. Confirmed by reading; cosmetic.

### 11. Same-kind events between one fragment and one version overwrite each other's link metadata
`genesis.cpp:388` writes `frag → version` with `link_type = e.kind` and metadata `{event, a_index, b_index}`; `Database::create_link` (`db/db.cpp:962-978`) upserts on `(src, dst, link_type)`. A fragment that occurs twice in version A and is deleted twice in B produces two `deleted_in` events whose links collapse into one, keeping only the last `a_index`. Idempotence holds; one of the two indexes is lost. Confirmed by reading.

### 12. `graph.structure` member reader fails as a whole on one malformed `metadata`
`structure.cpp read_members`: `json_extract(metadata, '$.units')` raises an SQLite error on a non-JSON `metadata` row, so one bad row (legacy/imported) removes every unit member with a `reader_errors` note. `json_valid(metadata) AND …` would skip the row instead. Plausible (depends on data).

## Checked and found sound (so the next reviewer need not repeat)
- `Database::create_link` upserts by `(src, dst, link_type)`, so a second `materialize` of the same chain at the same level creates no duplicate links; `test_text_genesis.cpp:196,404` compares canonical dumps.
- `myers_script` indexing (`off = max+1`, `v` of `2max+3`, trace slice `[off-d, off+d]`, `V(k±1)` guards) is in bounds; the backtrack uses the same stale/zero cells as the forward pass.
- Range-for over `.value(...)` temporaries in the new C++ is safe (the prvalue binds to the range); no `for (… : f().at("k"))` and no pointer kept across a reassigning call were found in `structure.cpp`, `genesis.cpp`, `align.cpp`, `fragments.cpp`, `ops.cpp`.
- Exceptions: the C ABI functions are under `guard_json`; `structure::structure` catches `std::exception` into the answer; the action path uses only the embedded text pack (the user-supplied `pack` overlay exists only on the C ABI, and the segmentation pack holds no regexes).
- `resolveDrop` self-exclusion for icons works (the dragged icon is the topmost hit and is skipped); `icon_to_desktop → move` then performs the D5 move.
- `arrangementPatch`/`diffPatch` produce RFC 7386 patches with `null` for removed positions; `readArrangement` drops null members; undo writes the full `before` value, so stale positions do not return from the host merge. `mergeSetting` is optimistic (local merge first), so two quick moves do not read a stale value.
- `desktop.arrange` client step: `dispatchEvent` is synchronous, `req.result` is read correctly; an unmounted/iconless desktop answers `arrange_no_icons`.
- `ProjectStructure` fetch effect keys on a serialised request and a module-level `api`; no refetch loop; `live` flags guard unmounted resolutions.
- `conversation.untrash` / `memory.untrash` accept `query` (the drop receipt's undo passes the right argument).
- Pointer drag state machine on icons: `pointercancel` is handled, pointer capture is taken on move/lift, the `touchmove` blocker is removed on end/cancel/next start; a `dragging` left behind by a lost `pointerup` heals on the next press.
