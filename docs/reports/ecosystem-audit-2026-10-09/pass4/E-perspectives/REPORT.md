## Konkretny odbiór

- **E: częściowo.** Rzeczywisty C++ `DefaultLayers` → `nativeResolutionFromResponse` → `compilePerspective` → `createPacketAdapter` → `selectPerspective` działa. Dwa profile zmieniają faktyczny zasięg. Exclusion przetrwał nowy proces native i zmianę packa, a E nie przywróciło ręcznego defaultu. To transfer stanu JSON między procesami hostowymi, nie dowód device/OnboardingStore restart.
- **A4-E-001: nadal wadliwe.** Dodanie nieużywanego adaptera innego źródła z deklaracją capability usuwa ostrzeżenie `adapter_capability_pending` aktywnego planu. Nie było wywołania tego adaptera. Deklaracja innego źródła nie dowodzi implementacji w źródle używanym przez plan. Test akceptacyjny FAIL; nie zaobserwowano automatycznej wysyłki ani rozszerzenia uprawnień.
- **A3-WEB-001: częściowo.** E udostępnia pole prawidłowego zewnętrznego profilu na żądanie bez renderera. Dodanie jednego nieznanego pola powoduje jednak `unavailable` również dla wcześniejszego znanego pola, ponieważ czytnik grafowy najpierw uruchamia ścisłe `registerProfile`. Walidacja wykonania może odrzucać nieobsługiwane dane, lecz odczyt struktury źródła nie powinien ich usuwać z dostępu. Połączenia edytowanego pola grafowego z istniejącym workflow runtime jeszcze nie ma.
- **D → native B4 → E: PASS po ID grafowym, BLOCKED po adresie źródła.** Oryginalny packet D (19 entities, 34 claims, 10 sources) zapisano w rzeczywistym native store, zamknięto, odczytano i odtworzono. Dopiero wynik replay podano E. Pole `/conversation/messages/0/text` jest dostępne przez ID encji. D `attrs.selector/source_version` nie mają natomiast istniejącego mapowania do E `ObjectRef.selector/snapshot`; adresowany w ten sposób fragment zwraca `selector_not_found`. Audyt nie dopisał adaptera maskującego tę lukę.
- **E → UI: BLOCKED kontraktem.** E1 nie dodaje komponentu ani produkcyjnego hooka. Raport autora sam zaznacza brak zastosowania proponowanego patcha eksportującego prywatny renderer. Nie instalowano patcha w audycie. Browser działa teraz: Chromium `141.0.7390.37`, uruchomienie + `setContent` + rzeczywisty odczyt DOM PASS. Dawne EPERM nie jest aktualnym powodem pominięcia przyszłej bramki UI.
- **A3-IMP-CH004: nadal wadliwe w aktualnym main.** Te same bajty JSON poza legalnym whitespace, po przekroczeniu 5 000 000 bajtów, zmieniają 1 rozmowę w 0. To mniejsza reprodukcja tego samego powodu co pass3; nie nowe finding ID. Pozytywny top-level conversation-array sentinel przechodzi tę samą zmianę strategii.
- **A4-CH-MOD001: nowe potwierdzone naruszenie.** `ModelRegistry` zachowuje pricing/description/unknown metadata w cache-list, lecz przy wspieranym opakowaniu `{"data":[...]}` odrzuca je i zapisuje utratę na dysku. Ponowne uruchomienie nie odzyskuje danych. Uszkodzony cache jest usuwany. `ModelPicker._build_list` konsumuje te pola do wyszukiwania/opisu ceny. Nie uruchamiano Kivy; ślad GUI jest analizą źródła, a loader, grouped i filesystem są wykonane.
- **A4-CH-VIEW001: nowe potwierdzone naruszenie R42.** Stary `GraphView` odfiltrowuje `AI`, `records` i incydentną krawędź przez ręczny próg długości/listę domenową. To tylko widoczność, nie usuwanie danych kanonicznych. Widok nie ma wejścia polityki pozwalającego zachować te węzły; akceptacja konfiguracji jest jawnie BLOCKED do podłączenia właściwego kontraktu.

## Metamorficzne i pozytywne mechanizmy

Sprawdzono równoważną kolejność kluczy obiektów, whitespace, UTF-8 kontra escape JSON, próg parsera, plik kontra ZIP stored/deflate, jawne ponowienie po niekompletnym małym JSON oraz zimny/rozgrzany indeks E. Kolejność wiadomości celowo **nie** jest neutralizowana: odwrócenie listy musi zmienić wynik. Nie przyjęto ogólnej równoważności `1` i `1.0`.

Rzeczywiste E kontynuacje w trzech porcjach odtworzyły 4 obiekty i 3 krawędzie. Jest to mały test budżetowanego kursora, nie dowód dowolnego crash-resume indeksowania. Unknown fields perspektywy przetrwały eksport/import z ostrzeżeniem. Istniejący headless workspace wybiera ID/run/focus bez renderowania; historyczny unlinked view pozostaje przy dawnym run. Rzeczywiste renderery listy i grafu w React SSR zachowują tożsamość oraz nie mutują wejściowych rekordów po zmianie szczegółowości/filtra. Jawnie sygnalizują prefix limitu. Widoczność, oddzielna lista analizy i przekazany permission context pozostają różnymi zakresami; nie jest to dowód natywnej ACL ani wykonania analizy.

E nie implementuje drugiego kanonicznego store: `createPacketAdapter` trzyma wejściowy packet jako widok i tworzy indeks referencji oraz projekcje na żądanie. Native resolution jest wejściem kompilatora; E nie składa własnych warstw/defaultów. `sourceText` i immutable packet nie stanowią dowodu zdalnego lazy transportu ani wszystkich osi cache/snapshot/write-back. Te granice pozostają jawne.

`coverage.json` zawiera 19 plików z nazwanymi zakresami, w tym 5 wcześniej nieopisanych plików głównego mianownika ChatADHD. Nie oznacza to pełnej weryfikacji tych plików. Siedem nowych plików E poza bazowym mianownikiem jest raportowane osobno; mianownik main 432 nie zmienił się. Pakiety napraw i bramki są w `handoff.json`; odtwarzanie w `REPRODUCE.md`; kod audytu pozostaje poza produktem.
