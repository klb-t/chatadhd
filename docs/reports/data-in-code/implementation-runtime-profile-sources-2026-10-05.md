# W11: jedno źródło presetu zużycia i jawny podgląd profilu

`loom/data/runtime/usage_policy.pack` jest teraz czytelnym artefaktem generatora. Jego `defaults` pochodzą wyłącznie z kanonicznego `loom/data/policy/usage_policy.pack` wątku 2. Nie zmieniono tego źródła, opisu deskryptora, rewizji ani schematu wartości. Dotychczasowy hash definicji i wartości pozostaje `e8b8d4e5b098213a421b88b1f11db949a8a6056838a2f8c9487303913da5a8bd`; przed zmianą surowy wrapper miał SHA-256 `85bea77d6f935c098ef3cb6de7ffc9fc9a07282e065bd9c10834f04b7d957335`.

## Receptura źródeł

`loom/data/runtime_sources.pack` (`loom.runtime_profile_sources/1`) zawiera ogólne receptury: `output`, obiekt szablonu `definition` oraz `projections` z `source`, `pointer` i `target`. Ścieżki są względne do `loom/data`, a oba wskaźniki używają RFC 6901. Pusty wskaźnik oznacza cały dokument. Projekcja zastępuje istniejący slot szablonu; nie scala źródłowych map i nie wprowadza nazwowego dispatchu. Typy, wymagane pola i zakresy wartości wynikają z końcowego schematu profilu. Parser zachowuje natywne signed/unsigned int64, a szersze skończone tokeny całkowite normalizuje do double tak jak nlohmann JSON: kwoty i otwarte rozszerzenia nie dostają sztucznego sufitu; schemat rzeczywiście całkowitego ustawienia odrzuci double.

Generator `loom/src/model/gen_runtime_profiles.py` najpierw czyta i waliduje wszystkie receptury, źródła oraz samodzielne profile, potem buduje wszystkie wyniki w pamięci. Dopiero po zakończeniu walidacji przygotowuje pliki tymczasowe i zastępuje wyniki. Błąd parsowania, powtarzający się klucz, liczba niefinitywna (także `1e999`), niepoprawny Unicode, ucieczka ścieżki/symlinku, cykl źródeł, nakładające się projekcje, brak wskaźnika albo niezgodność schematu nie zmieniają wcześniejszych artefaktów. Atomowe zastąpienie dotyczy pojedynczego pliku; nie obiecuje rollbacku po awarii systemu plików w środku końcowych zastąpień.

`python3 loom/src/model/gen_runtime_profiles.py --check` sprawdza **wrapper i embedding**. Zwykłe wywołanie regeneruje oba. Opcje `--data-dir` i `--output` pozwalają wykonać mechanizm na izolowanych kopiach danych bez modyfikacji repo. Logiczne ścieżki źródeł pozostają identyczne niezależnie od katalogu roboczego.

Rejestracja W12, gdy jego pack będzie obecny na przyjmowanej bazie, może użyć receptury `output: runtime/onboarding.pack`, `definition: {}` oraz projekcji `source: profiles/user.pack`, `pointer: /runtime_definition`, `target: ""`. Manifest opisuje tę drogę; nie aktywuje brakującego packa ani nie kopiuje jego danych. Powiązania ustawień ze stabilnymi ID i warstwy `DefaultLayers` nadal należą do wątku 12.

## API podglądu

`RuntimeProfile::defaults()` i `source_provenance()` udostępniają wartości presetu oraz tablicę źródeł. Każdy wpis źródła zawiera `path`, `pointer`, `target` i `raw_sha256`. Hash źródła liczony jest z oryginalnych bajtów, przed usunięciem BOM lub parsowaniem końców linii. Preset pochodny zapisuje zarówno źródło szablonu w manifeście, jak i źródła projekcji. Pozostałe domeny wskazują swój samodzielny pack.

`inspection()` addytywnie zwraca `definition`, `defaults` i `source_provenance` obok dotychczasowych `values`, `value_schema`, `hash`, `revision`, `domain` i `is_builtin`. Metadane źródeł są **poza definicją i hashem wartości**. Pozostają to źródła budowy presetu po zmianie efektywnych wartości przez `with_values`, `with_overrides`, `with_patch` i nakładkę plikową. `from_definition` nie wymyśla źródła: tablica jest pusta. `is_builtin` oznacza równość wartości z presetem, nie brak intencjonalnego nadpisania przez użytkownika.
