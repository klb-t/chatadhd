# S2 R34 (2026-10-15) - źródła narzędzi jako adapter (krok 8 PRZEGLAD_STRAZNIK_SRODOWISKA)

## Co zrobiono
- **Port `tool_source`** (`include/loom/tool_sources.h`, `src/tool_sources/`): interfejs `ToolSource` (`list_tools`, `call_tool`) i rejestr `AdapterRegistry<ToolSource, ToolSourceEnv>` (klucz wyboru `kind`). Pierwszy rodzaj: `mcp` (JSON-RPC 2.0: `initialize`, `notifications/initialized`, `tools/list` ze stronicowaniem, `tools/call`), transporty `stdio` (uruchomiony proces, wiersze JSON; tylko POSIX, na Androidzie/Windows `Unsupported`) i `http` (Streamable HTTP: odpowiedź JSON albo strumień SSE, `Mcp-Session-Id`, `MCP-Protocol-Version`, `DELETE` na koniec). Każda operacja otwiera własną sesję (bez stanu między wywołaniami). Żądania serwera (sampling, roots) są odrzucane, `ping` dostaje odpowiedź.
- **Dane**: profil `data/runtime/tool_sources.pack` (nazwy metod, wersja protokołu, nagłówki, limit czasu 120 s jako preset, flagi „nieznanych skutków”, szablon akcji, nazwy węzłów grafu). Nowy rodzaj źródła = wpis w `kinds` + `registry().add()`.
- **Ustawienia**: `tool_sources` (config, obiekt id -> {kind, transport, command/args | url, `access: {secret: <nazwa klucza w sejfie>, header?, scheme?}`, `env: {NAZWA: tekst | {secret}}`, label, enabled, `effects` dla źródła, `tools: {nazwa: {effects, hidden}}`}). Odrzucane: pole `access` z czymkolwiek poza referencją, url z danymi logowania. Nic nie jest wysyłane ani łączone, dopóki użytkownik nie doda źródła.
- **Nakładka katalogu** (`profiles/actions.pack`, nigdy pakiet dostarczany): jedna akcja na narzędzie, `tool.<źródło>.<narzędzie>`, `port: tool_source`, `action: call:<źródło>:<narzędzie>`, `origin: external`, `params` z `inputSchema` (typ, required, default, enum, opis), `hints` (adnotacje serwera, tylko zapis), `input_schema`. Zapis jednym `put` (cała mapa); tool zniknięte z serwera znika z nakładki; błąd połączenia zostawia dotychczasowe wpisy.
- **Preset „potwierdzaj”**: skutki = najgorszy przypadek + `effects_unknown: true`; dostarczana reguła `confirm:tool_source.unknown` (selektor `flag: effects_unknown`) w `action_rules.pack`. Adnotacje serwera (readOnlyHint itd.) niczego nie obniżają. Łagodzenie: `tool_source.trust {source, tool?, mode: allow|confirm|reset}` zapisuje regułę użytkownika (`tool_source:<źródło>:<narzędzie>`, nakładka `action_rules.pack`, zakres `person`) przez `rules_set`; alternatywnie `effects` w ustawieniu źródła/narzędzia.
- **Akcje zarządzania** w katalogu (`tool_source.list|sync|add|remove|trust`, HTTP `/api/tool_sources[...]`, `loom_invoke("tool_source", ...)`); `add`, `sync`, `trust` mają regułę potwierdzenia (preset). `remove` zdejmuje akcje, reguły, węzły grafu i wpis ustawień.
- **Graf**: `environment:service:tool_source:<id>` (klasa `service_environment`), `capability:...:tools` --`provided_by`--> `port:tool_source`, `access:...:vault` (odniesienia `secret_ref` + stan set/missing) --`stored_in`--> `vault:secrets`. Użyte tylko istniejące rodzaje krawędzi z R32 (`has_capability`, `provided_by`, `accessed_via`, `requires_access`, `stored_in`); `graph_views.pack` bez zmian.
- **Wywołanie** (`call:<źródło>:<narzędzie>`): wysyła tylko argumenty zadeklarowane w `params` (nie resztę żądania), zapisuje przebieg portu w grafie (`record_port_run`, bez treści argumentów), `isError` narzędzia = błąd kroku.

## Testy (`tests/test_tool_sources.cpp`, atrapa `tests/fixtures/fake_mcp_server.py`)
Wykaz -> wpisy nakładki; skutki nieznane mimo adnotacji; uruchomienie wymaga potwierdzenia, po `trust` jednego narzędzia przechodzi (pozostałe pytają), `reset`; wywołanie portu; źródło nieosiągalne; usunięcie źródła; graf; sekrety (kanarek w sejfie/env/nagłówku, brak w węzłach, nakładkach, config.json, odpowiedziach); HTTP z `ScriptedTransport` (JSON i SSE); nieznany rodzaj.

## Decyzje i cofnięcie
- Sesja na operację (bez trwałego procesu): prostota i brak wycieku procesów. Cofnięcie: trwała sesja w adapterze `mcp`, interfejs bez zmian.
- Skutki nieznane = wszystkie flagi „tak”: grupy użytkownika (`off_device`, `irreversible`, `spends_money`) też działają. Cofnięcie: overlay `profiles/tool_sources.pack` (`unknown_effects`).
- Reguła presetu w dostarczanym `action_rules.pack` (dane), nie w nakładce; użytkownik łagodzi własną regułą wyższego zakresu. Cofnięcie: usunąć regułę z pakietu albo `rules.disable`.
- Cofnięcie całości: `tool_source.remove` dla każdego źródła, usunąć `tool_sources.pack`, wpisy `tool_source.*`, regułę i generator.

## Dla S1 (nie edytowałem `src/actions/*`)
1. `ActionRunner::invoke_port` (src/actions/runner.cpp): dodać `if (port == "tool_source") return tool_sources::invoke(rt_, action, request);` (+ `#include "loom/tool_sources.h"`). Bez tego krok z portem `tool_source` zwraca „cannot be run as a step” (reguły, ×10, limity, pokwitowania działają do tego momentu; test sprawdza oba przypadki). Podobnie `environments` z R32.
2. Wywołanie `tool_source.call` przez `loom_invoke` omija reguły (jak port `storage`); klienci powinni używać `actions.run`.
3. Opcjonalnie: widok źródeł w web UI z `GET /api/tool_sources`.
