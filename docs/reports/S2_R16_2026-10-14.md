# S2 R16 - wstrzymanie x10 w wywołaniu mediów (ASR/OCR)

## Co zrobiono
- `MediaProviders` traktuje wstrzymanie przez straż użycia (use_model -> `State::Held`) jako **pauzę**, nie błąd dostawcy:
  `media_detail::send` zwraca `Errc::Paused`, a `try_providers` nie próbuje następnego dostawcy (brak wydatku "obok" straży).
- Nowe, addytywne API (`include/loom/media_providers.h`):
  `transcribe_bytes_resumable(...)` i `ocr_bytes_resumable(...)` -> `Result<MediaReply<T>>`,
  `MediaReply{ std::optional<T> value; Json pending; paused() }`.
  `pending` ma kształt `loom.action_usage_pending/1` (jak `usage_pending_of` w runnerze S1): `status, operation_id, receipt_id,
  baseline_key, projected, decisions, sent:false` + `media` ("media.asr"/"media.ocr") i `provider`.
- Wznowienie: ten sam wywołanie + `usage_confirmation = {approved, receipt_id, ref, operation_id}` (skopiowane z pending; ten sam
  mechanizm co czat). `approved:true` wysyła identyczne żądanie raz i próbuje tylko dostawcy, który wstrzymał (bez fallbacku);
  `approved:false` nic nie wysyła, odpowiedź to pending ze statusem straży (`denied`/`cancelled`).
- Dotychczasowe `transcribe*/ocr*` zwracają teraz `Errc::Paused` (zamiast `Unavailable`) przy wstrzymaniu, nadal bez fallbacku.
- Bajty żądania przy wznowieniu: **znaleziony błąd** - granica multipart była losowa (`build_multipart`), więc `request_sha256`
  różniło się i straż odpowiadała "operation ID already has a different estimate". Dodano `build_multipart(parts, deterministic)`;
  media (Groq) używają granicy wyprowadzonej z sha256 części -> żądanie jest bajt w bajt identyczne. Inne wywołania bez zmian.
- Testy: `tests/test_media_hold.cpp` (hold = pauza bez błędu i bez fallbacku, confirm = jedno wysłanie z identycznymi bajtami
  (porównane z niestrzeżonym żądaniem referencyjnym), nieudane potwierdzone wywołanie nie wydaje u drugiego dostawcy, reject nic
  nie wysyła, ścieżka normalna i fallback bez zmian, OCR).

## Co musi zrobić S1 (nie ruszałem src/actions/*)
W `run_media` (src/actions/runner.cpp) zamiast `rt.media().transcribe_bytes/ocr_bytes`:
1. wołać `transcribe_bytes_resumable` / `ocr_bytes_resumable`, jako ostatni argument przekazując `c.usage_confirmation`
   (puste `{}` gdy brak);
2. gdy `reply.paused()`: zwrócić `StepOutcome` Held z `out.hold = reply.pending` (tak jak dla zwykłego use_model, linia ~203);
   confirm runnera ponawia krok z `usage_confirmation` - dostawca, język, bajty muszą być te same (są - z kroku);
3. `Errc::Paused` z legacy API nie powinien się już pojawiać w runnerze po zmianie. Zaktualizować komentarz nad `run_media`.

## Decyzje i cofnięcie
- Pauza jako osobny typ odpowiedzi (`MediaReply`) + kanał thread_local (`HoldScope`) między `send()` a wejściem; dostawcy
  (`AsrProvider`/`OcrProvider`) bez zmian interfejsu. Cofnięcie: usunąć `*_resumable`, `HoldScope`, gałąź `Held` w `send()`.
- Potwierdzone wznowienie bez fallbacku (jedno wysłanie, jeden dostawca). Cofnięcie: usunąć parametr `once` w `try_providers`.
- Deterministyczna granica multipart dla mediów. Cofnięcie: `build_multipart(parts)` w `src/llm/media_adapters.cpp` (ale wtedy
  wznowienie ASR Groq się nie powiedzie przez niezgodny hash).
