## Reproduce without copying W2 implementation into this repository

After building the checked-out W5 static core with Ninja as in
[the native recipe](../native/README.md), fetch the pinned W2 branch if the Git
object is unavailable. Copy **only the three owned probe/helper files** to a
fresh external directory; the prepare script extracts the pinned four W2 files
there. Example from the repository root (use fresh paths):

```bash
mkdir -p /tmp/loom-w2-w5-probe
cp docs/reports/archive-import-2026-10-04-evidence/w2-integration/prepare_w2_overlay.py /tmp/loom-w2-w5-probe/
cp docs/reports/archive-import-2026-10-04-evidence/w2-integration/run_w2_integration.py /tmp/loom-w2-w5-probe/
cp docs/reports/archive-import-2026-10-04-evidence/w2-integration/test_receipt_evidence.cpp /tmp/loom-w2-w5-probe/
python3 /tmp/loom-w2-w5-probe/prepare_w2_overlay.py --repository-root "$PWD"
python3 /tmp/loom-w2-w5-probe/run_w2_integration.py \
  --core-build-dir /tmp/loom-thread5-native-build --acknowledge-after-core-ready
```

The last option acknowledges that the required W5 core build has completed;
it is a build-readiness check, not provider-spending authorization. The runner
records current source hashes, actual compiler/link commands and the new result.
Do not overwrite the retained original receipts with a rerun on a newer tree.
The runner relies on the recorded Ninja link recipe and OpenSSL-enabled profile;
these are reproduction requirements, not a universal build claim.
