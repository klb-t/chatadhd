# S2 R2 — metadane pól ustawień (2026-10-13)

## Zrobione
- DANE: `loom/data/runtime/settings_fields.pack` (profil runtime `settings_fields`, wbudowany generatorem
  `src/model/gen_runtime_profiles.py` do `runtime_profiles_embedded.inc`). Trzy części:
  `fields` (cechy pola: klucz, zakres config/secret, grupa, typ, `has_default`, opis, `sensitive`),
  `rules` (ogólne zasady `{scope, target{kind:settings_field,field_scope,key}, action:"edit", effect}`),
  `effects` (mapowanie efektu na etykietę: allow=optional, require_value=required, deny=read_only,
  require_confirmation=requires_confirmation; nieznany efekt przechodzi jako otwarty tekst).
  Brak zasady = allow = `optional` (R43). Wartości domyślne NIE są kopiowane — czytane z `config_defaults()`
  i `loom_config_defaults()`.
- Kod: `include/loom/settings_fields.h`, `src/core/settings_fields.cpp` (`settings_fields`, `settings_fields_problems`,
  `check_config_write`). ABI: `loom_settings_fields(ctx)` w `loom.h` + `capi_core.cpp`; JNI (`settings_fields`)
  i `LoomBridge.kt`; HTTP `GET /api/settings/fields`; CLI `loom config fields`; web: `SettingsFields.tsx`
  (tabela domyślna/reguła/opis), `settings/field-meta.ts`, `getSettingsFields` w obu klientach API.
- Walidacja: tylko efekt `deny` (read_only) odrzuca zapis (`loom_set_config`, `loom_set_config_json`, `loom config set`;
  PATCH /api/config zwraca 400). Dziś jedyne takie pole: `_config_version`. Wszystkie pozostałe pola i nieopisane klucze
  pozostają zapisywalne. `required` i `requires_confirmation` są informacją (wymusza je właściciel akcji, np. polityka zużycia).
- Sekrety: opisane (api_key = required, pozostałe optional, default absent, `sensitive`), wartości nigdy w wyniku.
- Testy: `tests/test_settings_fields.cpp` (kompletność w obie strony: każdy klucz z domyślnych ma opis, każde
  `has_default` odpowiada realnemu domyślnemu, sekrety providerów opisane, overlay użytkownika), `tests/test_capi.cpp`,
  `server/tests/test_server_smoke.py`, web `npm run test:settings-fields` (`web/e2e/settings-fields.mjs`).

## Decyzje i cofnięcie
- Reguła edycji jako szczególny przypadek ogólnych zasad (wytyczna koordynatora, §5). Cofnięcie: usunąć `rules`
  z packa i zwrócić pole `edit` w `fields`.
- `_config_version` jako read_only. Cofnięcie: usunąć jego regułę z `rules` (albo overlay `profiles/settings_fields.pack`
  z pustą tablicą `rules` — egzekwowanie idzie za efektywnymi metadanymi).
- Etykiety w pliku `cli.pack` (tekst pomocy) nie zmienione — plik pinned; `loom config fields` działa, ale nie ma go w `help`.

## Otwarte
- Dopisać `config fields` do pomocy CLI przez właściwy generator/pinned flow, jeśli właściciel chce.
- Skan źródeł pod kątem nowych kluczy `config().get("...")` poza listą domyślnych (obecnie lista dodatkowych kluczy w packu jest ręczna).
