## Findings and resolution

1. Initial integration inverted database and ChatEngine mutex acquisition:
   active task compilation held Database then requested ChatEngine, while send
   held ChatEngine then requested Database. Concurrent calls could deadlock.
   Final resolution consistently takes Database then ChatEngine for conversation
   resolution; compilation uses the same order. This also preserves serialized
   implicit first-conversation creation, avoiding the intermediate two-chat race.
2. Retained revision metadata needed full structural revalidation and unsigned
   successor overflow handling. Implemented; dedicated malformed-lineage and
   maximal-revision tests added.
3. Request/history filtering is scoped: independent memory/graph/knowledge
   channels are not filtered by W1. Documented and tested without disabling
   those capabilities by policy.
4. Source mutation during on_start must not change an accepted snapshot.
   The request and task provenance now come from one pre-persistence source
   selection; a callback mutation regression verifies the boundary.

The reviewer re-read the final changes and reported no remaining blocking
issue, subject to the coordinator's build and test results. Source binding
proves native text identity/optional quote occurrence; semantic fidelity,
external locator accuracy and supplied provenance dates remain unverified.
