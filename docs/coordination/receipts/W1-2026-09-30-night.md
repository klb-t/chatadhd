## Behavior changed

Selective successor bindings now keep history coverage from their exact
predecessor chain. Coverage prefers explicit current bindings, then the newest
ancestors; unrelated tasks with the same goal stay independent. A changed
active inherited source or an unbound active native edited sibling rejects
replacement before current-turn persistence. Explicit rebindings remain
available. An accepted newer sibling continues to count for later successors.

Native source text must be valid UTF-8 before acceptance. Retained snapshots
are checked for hash/quote/recompilation consistency and exact version ancestry.
No clause inference or semantic entailment is introduced.

Callback metadata replacement now preserves canonical acceptance independently
of optional context traces. Conflicting callback values are retained as evidence.
A process-local in-flight map closes the same-engine reentrant competing-root
window. Proper nested successors are still allowed. Custom context builders
are followed by revalidation before accepting the outer current turn; a stale
outer snapshot is rejected rather than silently recomputed. Callback exceptions
attempt canonical metadata recovery, then propagate the original exception.

The compiler does not change source rows. Changed current-turn text, role,
conversation or attachments stop transport; metadata is retained on the current
row when storage permits. This is acceptance evidence, not provider receipt.

## Remaining boundaries and next work

Ordinary message metadata remains mutable storage. The transient authority is
per ChatEngine, not a durable acceptance journal shared across engines/processes.
Arbitrary later metadata removal, moving the originating row, process crashes,
and later streaming callbacks are outside the strengthened retention guarantee.
Metadata on a moved row remains on that row; the adapter does not recreate or
move user data to preserve an artificial invariant.

Memory/context channels are still independently controlled and may contain
rejected content. Text bindings do not establish semantic entailment or freeze
attachment bytes. Provider failure does not undo acceptance, and reversed
completion order does not change the revision ancestry.

Next: extend actual C ABI/loopback transport evidence across revisions, then
assess the durable acceptance storage boundary, renderer/reference agreement
and measured scale/exception behavior. Follow the
[night queue](W1-2026-09-30-night-queue.md); the first queue item is addressed by
this verified increment. Start with actual C ABI/loopback revision coverage
on the next run; consult the latest publication receipt first.
