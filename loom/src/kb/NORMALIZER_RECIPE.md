# Native normalization recipe

`lexicons/stemming.json` is the single data authority for the native
`kb::Normalizer`. `loom.kb.stemming/2` adds a required `normalization` object.
The built-in copy is generated by `loom/tools/gen_kb_pack.py`; directory,
in-memory and overlay packs use the same validation and canonical pack hash.

| Field | Meaning and representation |
|---|---|
| `pl_character_cues` | Unicode characters that contribute the existing PL signal. Empty string disables this cue. |
| `vowels` | Unicode characters eligible for verbal repair. Empty string removes this table's contribution. |
| `non_ascii_vowel` | Whether an otherwise unlisted non-ASCII character also makes a verbal stem eligible. |
| `cvc_terminal_exceptions` | Unicode characters excluded from terminal consonant-vowel-consonant repair. Empty string removes these exemptions. |
| `undouble_exceptions` | Unicode characters exempt from final consonant undoubling. Empty string removes these exemptions. |
| `cvc_allow_non_ascii` | Whether short-CVC repair may inspect non-ASCII characters. Builtin false preserves the original recipe. |
| `undouble_allow_non_ascii` | Whether an eligible doubled non-ASCII consonant may be shortened. Builtin false preserves the original recipe. |
| `cvc_vowel_groups` | Required number of vowel groups in a short-CVC stem; nonnegative integer representable as `size_t`. |
| `restore_suffix` | Text appended by either configured-ending or short-CVC restoration. Empty string disables addition. |
| `guess_min_tokens` | Nonnegative integer representable as `size_t`: shorter texts use character cues alone. Empty token lists always produce `Unknown`. |
| `mixed_min_fraction` | Finite cutoff compared with both signal fractions, inclusive. |
| `pl_min_fraction` | Finite cutoff compared with the PL fraction, inclusive, with PL signal greater than EN signal. |
| `en_min_fraction` | Finite cutoff compared with the EN fraction, exclusive, preserving the existing boundary behavior. |
| `stopword_sources` | Ordered list of `{lexicon, fields, pl_signal_fields}`; each field references a string array in the named pack lexicon. Empty list disables these word-table contributions. |

Cutoffs above one can disable a comparison; negative cutoffs are valid.
They are settings compared with fractions, not probability outputs. Nonfinite
values are rejected by the shared pack validator.

The previous `pl` and `en` stemming tables remain unchanged. Their minimum
lengths, fold map, exceptions, rewrites, suffixes, markers and restoration
endings are still pack data. `min_token` and `min_stem` accept nonnegative
integers representable as `size_t`; the former artificial ceiling of 32 is
removed without changing either built-in value. `Lang` remains the existing native API: `Pl`,
`En`, `Mixed`, `Unknown`; adding an unsupported language does not implement
a new language capability.

To override this recipe, copy the current `lexicons/stemming.json` into a
user pack overlay, edit its data and pass it through
`Pack::load_with_overlay()`. This is an existing whole-document replacement,
not a second profile loader. A legacy `loom.kb.stemming/1` overlay must be
rebased on the `/2` template; retaining old table overrides preserves their
meaning while making the previously hidden recipe explicit. Incomplete or
invalid recipes fail validation with a file and JSON pointer. A smaller pack
may omit this method's lexicon entirely: `Normalizer::create(pack)` then
returns `Unavailable`. The legacy direct constructor requires a validated
`/2` recipe and is unsuitable for optional capabilities. There are no
hand-written fallback values in the normalizer.

For R40, the effective recipe must eventually come from the **shared W12
layer resolver**. A disabled or permanently excluded method must be reported
unavailable before constructing its normalizer; it must not be repaired by
silently restoring a built-in recipe. The plain pack overlay does not provide
persistent exclusion markers or a layer decision history. This increment
does not introduce a competing resolver.

For R41, the recipe and its canonical hash belong in a versioned method
definition using the accepted `loom.method_graph/1` contract in
`../packet/METHOD_GRAPH.md`. Registry execution and result-produced-by edges
are owned by W3. The pack hash already commits to the effective recipe; this
increment does not claim that older registry/legacy callers are graph-wired.

R42 classification: field names, pack filenames and version identifiers are
contract names; UTF-8 traversal, substring matching, counting, sorting and CVC
tests are operations. Character sets, restoration text, source lists and
thresholds are editable data.

## Reproduce default parity

Build the parent source and run
`python3 loom/src/kb/tests/run_normalizer_snapshot.py --build BUILD --output BEFORE`.
Build this increment, then run the same command with a fresh `--output AFTER`,
`--corpus BEFORE/corpus.json --compare BEFORE/snapshot.json`.
The probe calls the real native APIs; it does not duplicate their algorithm.
The frozen public development corpus and observed outputs are preserved in
the W4 report evidence. Provenance is separate from behavior, so intentional
pack/version hash changes cannot hide a normalization-output difference.
